# Image corpus provenance & shortcut audit — BASIRAH

Generated by `scripts/audit_image_corpora.py`, `scripts/corpus_classifier_test.py`
and `scripts/build_image_manifests.py`. Raw numbers live in
`datasets/image/audit/*.json`; this file is the human-readable verdict.

## TL;DR — the corpus as assembled is CONTAMINATED by metadata shortcuts

A model trained on this corpus can separate real from synthetic using **file
metadata alone, with no pixels at all**:

| feature set (NO pixel content)        | AUC   | corpus-ID acc (chance 0.562) |
|---------------------------------------|-------|------|
| pixel dimensions only (`w`,`h`,`px`,`aspect`) | **1.0000** | 0.750 |
| all metadata combined                  | **1.0000** | 0.675 |
| file size / bytes-per-pixel only       | 0.9995 | 0.696 |
| container format only (PNG vs JPEG)    | 0.9825 | 0.735 |
| EXIF presence only                    | 0.5000 | 0.562 (chance) |

Measured on 12,807 de-duplicated images (10,595 real / 2,212 synthetic),
`datasets/image/audit/corpus_classifier.json`.

**Do not report detector accuracy on this corpus as evidence of synthetic-image
forensics.** Any score above ~0.99 is consistent with a model that learned
"512×512 PNG ⇒ synthetic", which is a dataset artifact, not a detection result.

## Where the shortcut comes from (side by side)

| property        | real                        | synthetic              |
|-----------------|-----------------------------|------------------------|
| format          | 88.2% JPEG / 11.8% PNG      | **100% PNG**           |
| resolution      | 500×333, 500×375, 333×500 … | **512×512 (97.7%)**     |
| megapixels      | 0.1–0.5MP (88.0%)           | 0.1–0.5MP (97.7%)      |
| EXIF            | 0%                          | 0%                     |
| JPEG quality est.| ≈94                        | n/a (no JPEGs)         |

Two independent shortcuts compound:

1. **Container.** CommunityForensics-Small ships synthetic output as PNG
   (lossless, generator-native) while real photos arrive as JPEG. "Is it a PNG?"
   alone gives AUC 0.98.
2. **Geometry.** Generators natively emit 512×512 (LatDiff) or 256×256; the real
   photos are Flickr JPEGs at arbitrary sizes, heavily concentrated at
   500×375/500×333 (the classic Flickr long-edge-500 web thumbnail). Pixel
   dimensions alone give AUC 0.9998 — this is the single strongest leak.

Note the megapixel *buckets* look similar, which is exactly why bucket-level
reporting is misleading: the precise `w`×`h` values are almost disjoint between
classes even though total pixel counts overlap.

## EXIF: no shortcut, but also no provenance

**0% of images in BOTH classes carry EXIF.** Flickr30k images were stripped
during dataset preparation, so there is no camera-make signal and, importantly,
no way to audit camera provenance from this corpus. Camera diversity is
therefore **unverified** — the brief's requirement for varied camera sources is
NOT demonstrably satisfied, and no camera makes could be reported.

## Provenance gaps (recorded, not guessed)

- **CommunityForensics real images**: the `real_source` column is the literal
  string `"N/A"` for every `label=0` row in this release, so which real dataset
  (FFHQ / VISION / COCO / LandscapesHQ) an image came from is **not recoverable
  per-image**. Generator labels, by contrast, ARE documented and reliable.
- **Flickr30k licensing**: the HF dataset card has **no license field**. Original
  Flickr30k is research-use-only and images carry individual Flickr licenses.
  Recorded as UNCLEAR rather than assumed permissive.
- **CommunityForensics license**: CC-BY-NC-SA-4.0 — non-commercial, share-alike.

## Generator families — genuinely documented

Every synthetic image's generator comes from the source's own `model_name`
column. **Zero images have an undocumented generator**, and no generator was
ever inferred from a filename. Families obtained: **LatDiff, GAN, PixDiff,
Other** — enough for generator-held-out evaluation.

## Required mitigations before any detector is trained

1. **Re-encode / normalise format.** Convert a matched share of BOTH classes to
   a single container, or re-encode a random subset of each class at matched
   quality, so PNG-vs-JPEG carries zero label information.
2. **Resize-normalise or explicitly decorrelate geometry.** Resample both
   classes to a fixed size, or confirm accuracy holds when width/height are
   withheld, so 512×512 stops being a giveaway.
3. **Re-run the metadata-only classifier after mitigation.** Target: AUC ≈ 0.5.
   Only then does a pixel-based score mean something.
4. **Report a corpus-ID baseline.** If a model can identify which corpus an
   image came from, it is encoding the dataset, not synthetic media.
5. **Re-acquire real images with intact EXIF** if camera provenance matters.
